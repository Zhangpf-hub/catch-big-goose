# 21　触屏选中与高亮管线

日期：2026-10-25。证据对象为已有本地 402 冻结包，不代表当前线上账号或热更后的运行值。输入行为按本轮用户明确选择的“滑动切换、抬手确认”接入。

## 已确认的引用与调用

场景 `LevelManager._isMoveTouchChangeObj=1`；`_highLight` 引用 `sharedassets0.assets` 的 900、893，二者配置一致，均引用 Profile 863，`profileSync=0`。读取时使用完整命名空间的 DummyDll 类型树，验证内置头指针一致和严格字节消费。不能用 Profile 默认值替代组件实际序列化值。

编译方法证据位于 [selection-highlight-20261025](artifacts/selection-highlight-20261025/manifest.json)：

- `LevelTouch $j43524`：按住时走 `CheckClickRay`；触摸标记从按住转为释放时走 `GetTarget`。
- `CheckClickRay $j14625`：目标切换先对旧对象 `BeSelect(false)`，再 `BeSelect(true)`，调用 `HighlightEffect.SetTarget` 与 `SetHighlighted(true)`。射线落空走 `LostTarget`。
- `LostTarget $j7376`：取消对象状态、清空目标并关闭高亮；`GetTarget $j22244`：拾取当前目标并关闭高亮。
- `ObjectUnit.BeSelect $j7289` 除选中状态外还包含物理、摄像机方向偏移与 Tween 分支。这些是交互位移，不是高亮材质公式；当前项目迁移保留已有物堆物理和拾取动画，没有加入新的按住抬升。

主模块恢复 66 个方法体，次模块恢复 39 个；包含工具默认选取的其他关卡方法。两个分析模块均通过 WABT 和 WebAssembly 类型／控制流验证，依赖函数仍为导入，没有实例化或执行完整竞品游戏。

## Shader 程序恢复

普通 `Shader.export()` 只输出属性和 Pass：此 Unity 版本将有效变体放在 `m_PlayerSubPrograms`，通用导出器遍历的 `m_SubPrograms` 为空。不能将这个结构文本当作完整 Shader。

新工具 [recover_selection_highlight.py](../tools/competitor/recover_selection_highlight.py) 解压压缩分段，保留解压二进制，从中提取完整成对的 VERTEX／FRAGMENT GLSL 并记录段内偏移和 SHA-256。本次恢复 19 个 Highlight Plus Shader、44 段 GLSL；原始输入未修改。清单同时保留读取失败对象，不把失败对象计为已恢复 Shader。渲染状态直接从解析结构读取，保留 Blend 与 Stencil；通用文本导出器原本省略这两部分。

## 实际启用配置及公式

| 项目 | 场景值与执行含义 |
| --- | --- |
| 覆盖 | 黄色 `(1, .9215686, .0156863)`，强度 .5，混合 1；纹理与基础色参与覆盖颜色 |
| 覆盖动画 | 速度 1、最小强度 .5；三角波 `2*(1-min)*abs(.5-frac((t%1000)*speed))+min` |
| 描边 | 黑色，强度 1，宽度 .2，质量 3＝Medium，正常深度测试 |
| 外发光 | 强度 1.86，宽度 .25，质量 Medium，AlwaysOnTop，关闭抖动 |
| 发光层 | 一层，offset=1、alpha=1、颜色 `(1,.9647059,.1333333)` |
| 发光动画 | 位移宽度含 `1+.25*sin(_Time.w*speed)`；不是模糊贴图动画 |
| 法线 | Smooth：同位置顶点法线相加后归一化；效果网格与原网格分离 |
| 屏幕宽度 | 宽度先除以 100；八方向偏移的 Y 乘相机 aspect，顶点公式再使用投影矩阵及恒宽因子；不能直接解释成 .2 像素 |
| 淡入淡出 | 均为 0；覆盖与外发光仍有各自的周期动画 |
| 遮挡透视 | WhenHighlighted，强度 2.62，黄色 tint alpha=1，噪声 .47，边框强度 0 |

`QualityLevel.UsesMultipleOffsets` 的编译判断为 `(quality & -3)==1`，因此 High=1 与 Medium=3 都走八方向绘制，Highest=2 才走平滑模糊的 RT 管线。本项目迁移 Medium 八方向分支并保留 GPU instancing，不因为插件包含 Blur Shader 就增加全屏模糊。

Mask 使用 stencil bit 2；发光在轮廓外保留 stencil，描边在正常深度通过时写入 bit 2，并写深度。颜色层使用 `SrcAlpha / OneMinusSrcAlpha`。原版透视另有遮挡检查、模板及深度分支，不能将配置中的 seeThrough=0 误读为关闭。

## 项目适配边界

实现位于 [Unity 选中组件](../projects/catch-big-goose-unity/Assets/Scripts/GooseSelectionHighlight.cs) 与 [专用 Shader](../projects/catch-big-goose-unity/Assets/Resources/GooseSelectionHighlight.shader)。它们是依据编译证据转写的 Unity C#／HLSL，不是原 C# 工程，也没有引入完整 Highlight Plus 插件。

- 保留覆盖／描边／外发光的公式、实值、八方向、混合方式及启用的遮挡透视。未启用的内发光、目标图标、Highest 模糊等功能不进入当前选中组件。
- 将源 GL clip.z 映射到 Unity 各后端的统一深度约定，支持当前正交镜头、反向 Z 与截图 RT。
- 仅清理自身使用的两个 stencil 位，避免破坏其他渲染者的模板状态。
- 透视层用 GPU `ZTest Greater` 识别被挡像素，替代原插件周期性 CPU 遮挡粗筛及其模板调度；保留透视着色公式，但不声称遮挡判定逐像素等同原插件。
- 静态效果网格在原 CPU 网格释放前准备；蒙皮仅对当前目标复用 BakeMesh 容器，按原顶点分组合并变形后的法线。基础材质、UV、纹理和物理碰撞体不改写。

项目实施、构建与验收结果另记在 `docs/development-reports`，不把桌面结果写成真机通过。
