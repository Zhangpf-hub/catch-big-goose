# 06 复现工具与排错经验

## 先定位真正的代码和资源

缓存文件名只能作为线索。应先检查长度、头部和压缩格式；本例同名 wasm.br 仅一个零字节，真正代码在同 AppID 的安装分包。分包清单、每条目的大小和哈希见 [来源证据](证据/2026-10-22-生成与深度/来源/package-inventory.json)。不把“当前路径没有有效代码”写成“这个游戏无法取得方法体”。

资源读取、网格导出和方法分析分开进行。`source.json` 保留原数据；Blender/GLB 的处理差异另记。不能因为 GLB 验证通过就宣称已经重现 Shader，也不能把复制的竞品模型当成原创项目资产。

## 指针必须对照实际函数表

Il2CppDumper 给出方法声明和函数指针后，还需通过 WASM element table 映射到真实函数。WASM 标识符可含多个 `$`：`$fimport$510` 必须作为一个标识符按空白切分。早期用 `\$\w+` 会产生多余条目，后续指针全部错位；此问题已修复。

每个入口还需核对参数和返回值。`GetUnit` 与泛型 `Roll` 存在 ABI / 隐式返回缓冲差异，不能硬套声明解释。`SetMaxHeight` 等入口虽签名相同，但指向拆分重定向桩，仍排除。排除表保留原因，相关片段只作辅助追踪。引用的方法数必须是实际签名匹配并取得正文的数量，而非搜索命中数。

## 高级反编译失败后继续做可验证的工作

本例 WABT 的 `wasm-decompile` 报内存越界，改用 `wasm2wat`、字段偏移和类型签名直接分析。没有把失败输出当成 C# 源码。分析模块用外部依赖 imports 保留调用边界，先做名称、类型、控制流和引擎校验，再选择少量纯数学／状态函数执行。

隔离执行保留原五个方法体，只由宿主提供随机数、IL2CPP 字段描述和列表访问。测试不开放 wx、网络、文件或游戏初始化接口。这样能验证转写公式，但仍无法替代原游戏的配置和生命周期。跨语言比对应允许明确的浮点误差，选中索引和计数则逐步核对。

深度恢复示例（从工作区根目录运行，Python 路径按本机环境配置）：

```powershell
python tools/competitor/recover_methods.py --wat work/competitor-tools/main.wat --script work/competitor-tools/il2cppdumper/script.json --output work/competitor-deep --deep
node tools/competitor/validate_recovered.mjs
node tools/competitor/probe_original_algorithms.mjs
./tools/competitor/run_policy_tests.ps1
./tools/competitor/run_unity_algorithm_tests.ps1
python tools/competitor/archive_analysis.py
```

`work/` 中的完整 WASM、巨型 WAT 和 Dumper 输出是本地研究中间产物，章节交付只归档相关正文、索引、校验与测试。单独的 `selected.wat` 可供审阅，但不是完整游戏可运行包。

## 验证时避免误报

1. C# 语义编译仅说明引用和类型正确，不证明 Unity 物理正常。首轮许可证阻塞时只能报告编译检查；激活后才补做本轮 10 项编辑模式和 71 项开发包检查。
2. 隐藏渲染与禁用碰撞要分开。测试必须确认底层碰撞仍存在，并实际移走上层，观察重新显示、唤醒，避免只有字段变了。
3. 调试清空库存会绕过手动可见性检查，必须另测隐藏物件手动拒绝；不能拿自动通关证明鼠标总能点击到所有物件。
4. 测试前移走旧结果文件，避免用陈旧 PASS。保留源码哈希及独立 QA 构建，避免并行迁移工作覆盖同名玩家包。
5. 构造函数默认值与序列化覆盖分开；单个样本与全模式分开；概率补偿与实时难度干预分开。每次结论都回到对应证据。
