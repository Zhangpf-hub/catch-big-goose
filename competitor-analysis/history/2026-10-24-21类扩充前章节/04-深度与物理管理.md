# 04 深度与物理管理

2026-10-23 新取得场景序列化值，已更新 Unity 基线。下表的竞品列仍明确列构造默认，场景实际值另见 [第 08 章](08-实际关卡权重与深度参数.md)。序列化与在线最终值继续区分。

## 动态深度阈值

**【确认·静态】** `GetDynamicVisibleHeight(index, multi)` 读取高度前沿与可见深度参数：

```text
frontier = index == 1 ? _minTouchHeight : _p2MinTouchHeight
ratio = Clamp01((_minVisibleY - frontier) / _minVisibleY)
depth = Lerp(_visibleMinHeight, _visibleMaxHeight, ratio)
threshold = frontier - depth * Min(multi, 1)
```

其中 `_minTouchHeight / _p2MinTouchHeight` 的字段偏移为 264 / 328，深度最小／最大值为 340 / 344，参考高度为 348。`CheckVisible` 比较的是 Transform **世界坐标 y**。可见性与刚体检查分开调用，不能把隐藏和删除物理对象混为一件事。

**【确认·隔离执行】** 原阈值方法在 `multi = 1 / 0.75`、不同前沿高度下执行 202 组样本，与 C# 对照通过。我们额外加入的参考高度为零防护不属于原公式的已验证域；正式配置要求参考高度大于零。

## 前沿如何下降

**【确认·静态】** `CaculateMaxHeight` 在剩余集合中查找最高候选，排除已存放项，并在变低时更新记录。`SetMinTouchHeight` 的普通分支每次下降不超过 `_maxOnceTouchHeight`：

```text
newFrontier = highest < previous
    ? Max(previous - maxOnceStep, highest)
    : previous
```

强制分支可以直接重设。正常过程是逐步向下开放，打乱等重排后的处理需要与普通下降分开。自有 `PileDepthPolicy.Descend` 对齐普通分支，重排后主动重建前沿。

## 隐藏、刚体和支撑分别是什么

**【确认·静态】** `ObjectUnit.SetVisible` 修改 `col` 所在 GameObject 的激活状态、Renderer.enabled 和 `isHiding`；这个方法中没有修改 `realCol`。但仅凭字段名还不能确定两个碰撞路径在所有模式中的完整分工。

`CheckRigid` 在深度之外还检查当前缩放与目标缩放近似相等；`HideRigid` 检查不可抓、已存放、已选中等状态，在非强制分支存在速度 0.2 的保护。`SetRigid` 最终设置 `Rigidbody.isKinematic = !usePhysic`。这是切换刚体模拟，不是删除碰撞体。

**【项目适配】** 自有物件分别持有 `DepthVisible`、`DepthHeld`：

| 状态 | 渲染 | 手动点选 | 刚体 | 支撑碰撞 |
| --- | --- | --- | --- | --- |
| 正常可见 | 开 | 允许 | 动态或深度托住 | 保留 |
| 深层隐藏 | 关 | 拒绝 | 满足静止条件后设为 kinematic | 保留 |
| 消除／暂存的已取物件 | 原玩法处理 | 不再作为场内候选 | 原玩法处理 | 不作为场内支撑 |
| 上层移走／打乱后恢复 | 重新检查，打乱立即显示 | 显示后允许 | 立即唤醒，再等待稳定 | 保留 |

深度隐藏仅关闭 Renderer，不停用物件根节点或全部 Collider，确保底层仍能支撑上层；手动点选由 `GooseGame.Pick` 单独检查。自动化规则验收可绕过显示检查以验证库存清空，这不等于真实用户可点击隐藏件。

下沉后若只按高度隐藏，残局里的孤立底层也可能消失。我们加入五条向下遮挡射线，只有五个探针都先命中另一个更高物件时才允许隐藏；这只是本项目的稀疏堆保护，并非已恢复的竞品逻辑，也不是精确的屏幕遮挡求解。

移除任意场内物件后，保守地唤醒所有深层托住的剩余物件，避免支撑关系断开后悬空。打乱与返回场内也重置保护时间。待物件稳定后重新按深度托住；没有为了凑数量而立即冻结仍在运动的物件。

## 参数的证据等级

| 参数 | 竞品构造函数默认值【确认·静态】 | 自有配置【项目适配】 |
| --- | --- | --- |
| 可见深度最小／最大 | 4 / 6 | 0.4 / 0.5（场景值 4 / 5） |
| 深度参考高度 | 20 | 2.1（场景值 21） |
| 刚体深度乘数 | 0.75 | 0.5（场景值 0.5） |
| 单次前沿下降上限 | 1 | 0.05（场景值 0.5） |
| 隐藏刚体的速度保护 | 0.2，来自方法体 | 线速度 0.2，另加角速度 0.6 |
| 最大物理对象数 | 80 | 70，仅软预算诊断（场景值 70，启用条件另查） |
| 分帧创建数 | 3 | 保留自有投放节奏，未声称逐项一致 |
| 创建间隔／物理创建间隔 | 0.03 / 0.04 | 保留自有协程节奏 |
| 物理创建增长速度 | 0.2 | 不直接照抄 |
| 稳定等待、迟滞、生成／扰动保护 | 未证明存在同样处理 | 0.35 秒、0.06、0.8 / 0.8 秒 |

竞品构造默认值本次已确认被场景序列化资源覆盖；自有场景尺度不同，不能把十倍缩放写成已知的原版单位换算。当前 0.4 / 0.5 / 2.1 来自场景基线乘本项目选定的 0.1 尺度。`maxDynamicBodies` 超过 70 时仅暴露诊断标记，不保证任意时刻动态体都小于 70。

Unity 的 kinematic 语义可对照 [2022.3 Rigidbody 官方手册](https://docs.unity3d.com/cn/2022.3/Manual/class-Rigidbody.html)。本项目还用实际 Unity 测试确认隐藏根节点仍激活、碰撞开启、释放后恢复动态。
