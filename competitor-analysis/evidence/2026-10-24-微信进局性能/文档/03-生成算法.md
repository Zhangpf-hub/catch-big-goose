# 03 生成算法

2026-10-23 已恢复实际本地关卡权重，并区分“目标层分布、等权选普通类型、普通三件组配额”三个阶段，详见 [第 08 章](08-实际关卡权重与深度参数.md)。本章解释随机选择器和原有有限库存适配，不把所有权重都说成类型入选概率。

## 历史补偿加权抽取

**【确认·静态】** `CreateLevel` 存在对 `KFakeRandom<int>.Roll()` 及后续移除候选的调用。`RollIndex` 累加当前 `pro`，在 `[0, sum]` 抽取，选择首个累计值严格大于随机值的候选，边界回退到最后一个。随后总抽取次数递增，调用概率修正方法。泛型上下文 RGCTX 的槽位 23、24 分别核对为 `CalProToAlloc`、`AllocPro`。

设初始归一概率为 `p0[i]`，当前权重为 `p[i]`，总抽取次数为 `N`，命中次数为 `hit[i]`。本次选中 `k` 后：

```text
N += 1
hit[k] += 1
real[k] = hit[k] / N
diff = real[k] - p0[k]
transfer = diff > 0 ? min(diff, p[k])
         : diff < 0 ? max(diff, p[k] - 1)
         : 0
p[k] -= transfer
当 transfer != 0 时，对 i != k：
    p[i] += transfer * p0[i] / sum(p0[其他候选])
    real[i] = hit[i] / N
```

它依赖抽取历史，与每次独立均匀随机不同。另一个 `RealRandomRollIndex` 入口只按当前权重抽取、增加总次数，不调用上述补偿。不能假定全部模式都使用同一路径。

**【确认·隔离执行】** 原 `RollIndex / CalProToAlloc / AllocPro` 方法体在内存沙箱中连续执行 2,048 次，覆盖 `.25/.5/.25`、四项均匀、`0/.5/.5`、单候选。与自有 C# 的未加防护模式逐步对比命中索引、概率和计数，通过。随机源、IL2CPP 字段描述和 List 访问由测试宿主适配，未执行完整游戏。

直接反复调用辅助入口的测试中出现 218 个概率越界状态。测试未模拟完整 `Roll / Check / RemoveItem` 生命周期，因此**不能据此声称正式竞品存在概率漏洞**。`Check` 与 `RemoveItem` 的方法体已保留，但自有项目没有宣称完整复刻其候选生命周期。

## 自有有限库存的接入

**【项目适配】** [GooseGeneration.cs](../unity/Assets/Scripts/GooseGeneration.cs) 的 `FairWeightedSelector` 实现上述核心补偿；正式默认模式加入 `[0,1]` 限制和重新归一，防止累计分布失去单调性。未加防护模式仅用于原 WASM 对照测试。

`FinitePileGenerator` 未配置组数权重时保留每类 `groups × 3` 件；配置 `groupWeights` 后通过 `WeightedGroupAllocation` 分配总组数，再用抽取顺序权重决定投放先后。库存耗尽后移除该类并重建剩余选择器。重建会重置补偿历史，是我们适配有限库存的选择，不等同于竞品 `RemoveItem`。当剩余库存的顺序权重全部为 0 时改为等权，保证固定库存能投放完。

三档普通件仍为 48 / 54 / 81，金鹅独立加入，冰封配额保留；消除后不补货。权重改变顺序和埋藏关系，不改变本局各类总数量。`ThemeDefinition.itemWeights` 可提供与 `items` 同序的权重，未配置时名义等权。固定 xorshift 种子属于自有可复现设计，未证实竞品同样使用。

## 位置权重

**【确认·静态】** `GetWeightMultiPart` 用 `(weight[i].x + weight[i].y) × weight[i].z` 作为区段权重，经 KFakeRandom 选段，再在该段调用 `GetWeightRandom`。不能在未恢复配置时认定第三分量 z 总等于区间宽度。生成协程存在真实调用，结果参与位置向量缩放，不只是闲置工具类。

端点权重近似相等时为均匀采样；否则原指令对应：

```text
r = Random.Range(0, (w0 + w1) / 2)
d = w1 - w0
b = 2 * w0 / d
t = sqrt(2 * r / d + b*b/4) - b/2
result = min + (max-min) * t
```

**【确认·隔离执行】** 原区间方法在递增、相等权重域执行 404 组样本，与自有算法数值对照通过。原式对递减权重可能离开区间，实际竞品配置域尚未恢复，未把它当成通用公式直接复制。

**【项目适配】** `WeightedPosition.Linear` 使用数值稳定的等价反解，在已验证递增域保持一致，并扩展到递减、零端点和有限输入检查。自有 `Centered` 是两段对称中心偏重曲线，边缘权重默认 0.4；仍保留原分层格点布局，只调整格点内抖动。对称段质量相同，选段使用确定性随机值等分，而非完整复制竞品分段 KFakeRandom 历史。原竞品空间区段、旋转和各轴实际参数仍待确认。

## 未确认的生成结论

本地初始权重已归档。**【推测／待确认】** 网络和 AB 覆盖后选中的权重／候选集合、完整移除及重置策略、实际空间曲线与全部模式最终数量。已读 AB 分支按层读取 `ReduceType / ReduceGroup`，不能进一步推导为按玩家槽位实时操控难度。完整三件库存不等于几何遮挡下必可解。
