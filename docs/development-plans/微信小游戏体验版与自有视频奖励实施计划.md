# 微信小游戏体验版与自有视频奖励实施计划

## 目标与范围

- 把 `reference-projects/catch-big-goose-cocos/` 的 Cocos Creator 3.8.8 游戏做成**微信小游戏体验版**，供指定朋友在微信中体验，不向公众上架。
- 失败救场、补道具时播放**自有 MP4 视频**，播放完成后发游戏内奖励；续挑战次数可作为第三个入口。
- 不使用微信激励视频广告 API、不申请流量主、不获取广告收益。保持 H5 版正常可玩。
- 本文是待实施计划，并不表示已有微信构建或真实视频播放功能。朋友须获得体验权限；如需面向所有人开放，另走正式发布与审核。

## 当前状态与先决风险

- 目前只有 `reference-projects/catch-big-goose-cocos/build/web-mobile/` 构建；`reference-projects/catch-big-goose-cocos/assets/scripts/core/GameManager.ts` 的 `ensureDaily`、`offerPropRefill`、`rescue` 均直接发奖，是视频接入点。
- **优先解决启动**：`reference-projects/catch-big-goose-cocos/assets/scripts/core/JoltLoader.ts` 通过 `location.href`、`new Function` 和原生动态 `import()` 加载 H5 根目录的 `jolt-glue.js`。微信小游戏环境不等同于浏览器；`reference-projects/catch-big-goose-cocos/build-templates/web-mobile/` 与 `reference-projects/catch-big-goose-cocos/preview-template/` 不会自动成为微信小游戏模板。Jolt WASM 的加载与包体是第一项技术闸门。
- 除 Jolt 外，还需真机检查 GLB/音频加载、引导、触摸、`SaveData` 本地存储和结算流程；不能把“构建成功”当作“可玩”。

## 阶段一：账号及体验权限

1. 准备微信小游戏账号、真实 AppID 和微信开发者工具；确认账号有上传开发版本和设置体验版的权限。不要把普通微信小程序或测试 AppID 当作最终体验账号。
2. 在微信公众平台后台将指定朋友添加为体验成员，再发体验二维码；人数和入口以后台实际显示为准，二维码并非任意朋友均可访问。
3. 记录注册、实名或认证等后台提示及可能费用；此路线无须申请流量主或广告位。

**验收**：确认上传者、体验者名单、账号未满足条件及对应处理方式。

## 阶段二：构建与真机可玩性

1. 使用 Cocos Creator 3.8.8 新增**微信小游戏**构建目标，保持 `web-mobile` 产物及现有 H5 启动方式不变。
2. 为微信环境验证或适配 `JoltLoader.ts`、WASM 胶水及资源位置；以微信开发者工具和真机的实际运行能力为准，不直接照搬 H5 动态导入方案。必要时调整胶水生成脚本与微信构建模板。
3. 检查包体/分包、远程资源和域名要求、GLB/音频、存档、帧率和启动耗时。
4. 真机走通：首页 → 选难度 → 引导 → 操作物件 → 用道具 → 结算 → 重开；回归 H5。

**继续条件**：至少一台真机完成整局，无启动卡死、关键资源缺失或无法操作。未通过则先处理平台兼容，不进入视频开发。

## 阶段三：自有视频与奖励

1. 准备具有使用权的短 MP4 先做验证。评估随包与远程托管：大文件尽量不进主包；远程地址需核实 HTTPS、后台域名要求、弱网加载及存储/流量成本。
2. 封装统一的视频播放结果：`completed`、`closed`、`error`、`timeout`；限制同时仅有一次播放请求。在微信真机验证 Cocos `VideoPlayer` 完成事件、遮挡层级、声音及切后台/返回。
3. 把 `GameManager.ts` 的失败救场、补道具接入；续挑战次数可随后接入。按钮说明写成“观看视频后领取”，不要称为微信官方激励广告。
4. **仅对当前请求的首次有效完成回调发一次奖**。提前关闭、失败、超时不发，显示重试或返回；防重复点击、重复回调、切场景后旧回调发奖。H5 保留现有行为或单独启用明确的模拟测试模式。
5. 完成事件仅是客户端播放状态，不是平台广告观看凭证，也不能防范快进或篡改客户端；未来若变成真实广告变现，需要重新设计。

**验收**：分别测试播放完成、提前关闭、加载失败、超时、双击、切后台和重进；奖励恰好发一次或不发，游戏音频和操作恢复正常。

## 阶段四：朋友体验

1. 开发者工具检查日志 → 上传开发版本 → 设为体验版 → 添加体验成员 → 分发二维码。无需以正式向公众发布作为测试前提。
2. 邀请至少一位朋友真机验证首次进入、完整一局、各视频入口、弱网、退出视频、切后台、存档与次日挑战次数。
3. 收集机型、微信版本、日志和加载耗时；修复阻断项后更新体验版，并再次回归 H5。

**验收**：指定成员可在微信扫码进入并完成一局，视频奖励逻辑正确，且不依赖本机开发服务器。

## 门槛、费用及非目标

- **必要条件**：小游戏账号与 AppID、上传及体验权限、真机可运行的构建、已添加的体验成员、合法可用的视频素材。
- **可能费用**：注册/认证按官方后台当时提示，远程视频可能有存储/带宽费，另有素材制作和设备成本；自有视频不需购买微信广告位或按观看次数向微信支付广告接入费。
- **本期不做**：真实微信激励广告、收益结算、流量主申请、公开上架或绕过平台审核。含第三方商业推广、跳转或他人内容的视频，仍需核实授权与平台规则；体验版并不免除内容合规要求。
