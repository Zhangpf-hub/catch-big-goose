# 正常模式表层性能与摇动重排计划

日期：2026-10-26。状态：独立 Agent 审批通过；按下列顺序实施并完成独立验收。

## 目标与证据边界

当前工程 `projects/catch-big-goose-unity`，Unity 2022.3.62f3；微信入口 `builds/catch-big-goose-wechat`。保持五主题、15/300件库存、模型材质与现有画质。原始竞品资源、冻结证据保持完整。

目标是只让暴露表层承担动态物理、摇动与重排，隐藏下层保留静止碰撞支撑，不受重力或施力。渲染集合、可交互表层、静止支撑须明确区分，侧面可见支撑不必全部动态。移除后局部晋升新暴露物件；禁止用全体唤醒解决浮空。

竞品研究以 WASM 实际调用链和序列化参数为证：分别标注已证实、项目适配和未知项。已有报告的 Windows 30Hz数据不能证明微信真机流畅。真机目标为正常模式300件持续30 FPS，P95≤36ms、>50ms慢帧比例≤1%，连续拾取/摇动/重排后自然恢复，无持续GC或内存增长；没有真实设备采样时不得标记真机通过。

## 已定位问题

1. `GooseGame.UseProp(2)` 对全堆 `DisturbAll`、显露、随机投放并逐件求空位，违背仅表层且制造物理/查询尖峰。
2. `GoosePileDepth` 在剩余≤70时强制全显示、全动态；大堆动态阈值又可能仅剩3–10件可摇，导致效果弱。两端都需消除，不能只加大力。
3. 拾取按水平半径解冻整列；容器收拢也可解冻隐藏下层。需要限定高度邻域与独立的结构支撑更新。
4. 遮挡五射线/件、周期性全堆扫描排序、每帧穿底几何检查存在Wasm开销。应缓存并分摊查询，静止时不重复做相同工作，移动/拾取/视口变化失效时重算。
5. 传感器窗口内低幅回调可覆盖已接受强峰值；同一方向施力与较小冲量上限可能只滑动。需保留已接受峰值并实测位移/转角/邻居变化。
