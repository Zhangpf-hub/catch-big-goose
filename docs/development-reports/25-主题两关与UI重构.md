## 关卡配置

正式入口改为每主题第一关和第二关。第一关由 12 件普通物品和 3 件主题目标组成，选中两种普通物品各 6 件，不限时。早餐普通候选为油条、虾烧卖、豆浆中的两种；烧烤为串和玉米；乡村及杂货按各自原始第一关候选抽取。目标与普通物品的索引、权重分开解析。

玩具第一关是本项目自定义：鳄鱼 6 件、恐龙 6 件、数字积木目标 3 件；配置中标记 `custom=true`，不称为竞品普通主线第一关。

模型池大小、每层选中类型数、三件组配额和单局总库存是四个不同概念。完整模型池不意味着一张截图中会出现全部类型；按原权重取整后，个别选中类型可能为零组。每层普通库存保持完整三件组，末类接收余数组数，不通过补入无关物件凑数。

源参数采用已恢复的冻结 402 表，不启用未知账号 AB、服务器分桶或热更覆盖。源高度和场景尺度作为明确字段保留；本项目使用当前圆形容器、物理尺度和预加载适配，不宣称世界单位或在线玩家难度逐项相等。

## 接口、流程和存档

`Data/theme-rounds.json` 保存十个关卡；`ThemeRoundCatalog.Create(theme, stageIndex)` 只接受 0、1。`PileLayerDefinition` 增加独立候选 ID 与配额权重，候选池不足时直接报错。首页预加载、正式开局和界面数量提示均读取这一份配置。原 `CoreRoundCatalog` 的 15 / 60 / 300 档仅供历史回归和独立对照，不再作为正式三档入口。

新进度和成绩使用 `story1_` 键并按主题隔离。旧难度和旧成绩保留，不自动视为新两关通关。第一关免费，通关按钮进入第二关；第二关在资源准备成功后扣一次挑战机会，失败重试当前关不重复扣除。第二关完成后提供重新挑战，正式入口没有第三关。

源码与当前发行资源独立核对工具为 `tools/competitor/verify_two_stage.py`，使用明确的源键检查名称顺序、候选、目标、各层件数、类型数、权重及时间，不使用名称相似度选表。

## 资源与视觉

普通道具从 80 类补齐为 116 类，使用本机缓存和 2.3.75 版本公开资源分包；下载地址、哈希及原始提取文件保留在 `work/two-stage-20261025/` 和 `reference-projects/competitor-goose/2026-10-25-complete*`。蒙皮目标物按原始预制体姿态烘焙成静态道具，源骨骼输入另存。116 类保留 191 个原始材质分组，继续采用 R3 的 UV、MatCap、玻璃和独立碰撞代理；原 Shader 程序没有完整恢复。

首页使用独立相机绘制真实白色展台、柴犬与当前主题物件，替换原静态道具桌。柴犬的呼吸、轻晃、点击弹跳和声音反馈在运行中执行；首页音乐遵守原静音偏好。界面采用新生成的立体黄／蓝按钮、暖色边框、奶油色面板及三个道具插画，文字仍由 Unity 绘制。素材与完整提示词位于 `source-assets/models/candidates/two-stage-ui-20261025/`，切片位于 `projects/catch-big-goose-unity/Assets/Resources/Textures/story-ui/`，采用内置 image_gen 生成。

正式玩法保留项目当前五套主题圆盘／圆筐、背景与收缩、摇动流程；恢复出的五套原始场景模型保留为独立陈设候选，冻结包中 `sceneDressing=false`，避免额外容器悬在画面上方。陈设不计入库存或碰撞。初始场景相机为 64 度俯角，少量残局按圆筐规则逐步增加俯角。交互按钮按 720 参考宽度提供至少 88 单位触控尺寸，对 360 逻辑像素手机宽度为 44 像素。图标转台相机使用独立层，避免后台预加载场景混入透明图标。

未使用的旧首页插画和五张旧主题背景已移到 `SourceAssets/BeforeTwoStage-20261025/retired-ui/`，保留元数据与清单；没有为压包缩小模型原贴图或降低短片画质。

## 验收与复现

- `npm run check` 执行编辑模式回归，包含五主题两关各 100 个种子的库存、候选、配额与确定性检查。
- `npm run qa` 构建并执行十关运行验收；可用 `tools/unity/run-story-acceptance.ps1 -SkipBuild` 重跑已有开发包。
- `GooseStoryFlowAcceptance` 检查首页真实按钮、第一关免费、通关进入第二关、次数扣除、失败重试及主题进度恢复。
- 验收开发包使用独立 CompanyName 隔离 PlayerPrefs，避免并行任务相互修改挑战次数。正式包保留原 CompanyName 和正式存档命名空间。
- `story-acceptance.json` 同时记录正常速度屏幕点击样本与独立自动库存遍历。前者提供耗时、槽位压力和道具使用观察；后者检查完整清空，不代表人类通关率或竞品胜率。
- `model-preview-clean/` 保存 464 张实际四视图和 232 张图标；透明图标入库前检查真实 alpha 和四角，防止其他场景混入。
- 三种窗口及模拟安全区的截图、图形检查、原版并排对照，以及从实际采集帧编码的无音轨动画片段保存在同一交付目录。

Windows 强制移动档截图、微信编译和开发者工具预览不能替代 iPhone／Android 真机触控、传感器及持续帧率测试。本轮实际结果以最终交付 JSON 为准，保留失败后修正的中间日志。
