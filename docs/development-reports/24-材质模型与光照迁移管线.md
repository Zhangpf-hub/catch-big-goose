# 24 · 材质、模型与光照迁移管线

日期：2026-10-25。交付标识：**20261025-R3**。承接第 23 章诊断。本章将源资源事实、项目渲染适配和手机待验证项分开记录；不把近似 Shader 写成恢复了竞品完整程序。

## 1. 本轮实际范围

当前工程的五主题已使用缓存中的竞品物件：早茶 17 类、烧烤 17 类、乡村 18 类、玩具 21 类、杂货 7 类，共 **80 种**。本轮保留这套选择，以及当前类型权重、库存、相机、物件尺寸、分层与深度配置。

**【确认·资源】** 80 件物件对应 **102 个原材质分组、141 张按内容与颜色／数据用途去重的纹理、9 个玻璃／晶体材质、11 个没有基础色贴图的材质**。后者使用颜色／MatCap，缺基础色贴图本身不是丢失资源。源 Shader 名称如下：

| 源名称 | 材质数 |
| --- | ---: |
| ToonLite1 | 76 |
| ToonLite2 | 6 |
| ToonLite1MulMatcap | 8 |
| ToonLite1_ShiftHue | 2 |
| ToonGlassCus | 5 |
| ToonGlass | 3 |
| CustomCrystal | 1 |
| ToonEffectFull | 1 |

其中 8 个材质带双 MatCap 分区输入；21 个材质的 AO 参数大于零且具有对应贴图。已读取源参数的 `_IsUseNormalMap` 均为 0，因此本轮没有仅因存在法线贴图就开启法线分支。名称不是完整公式的证据；ToonLite2、ShiftHue、Effect、Crystal 的特殊分支仍未完整还原。

**【确认·项目】** 候选导出逐件校验三角面数与迁移前预算完全相同，本轮不增加细分；当前 80 件中最高 **2,472 三角面**。按原材质分组拆开透明层，同一材质的独立零件合并到同一渲染器，共 102 组。独立低面碰撞代理继续用于游戏，未将渲染网格改作碰撞体。

容器沿用当前项目资源，转换为同一不透明 Shader 以接收阴影；**本轮没有重新提取竞品容器或补回容器旧图集已经损失的细节**。不能把“80 件道具材质迁移完成”扩大为所有环境资源均像素一致。

## 2. 可重复执行的迁移流程

在工作区根目录执行：

```powershell
./tools/unity/build-reference-look.ps1
# 已有通过校验的候选时跳过 Blender 重导出：
./tools/unity/build-reference-look.ps1 -SkipModels
# 最后同时完整重建微信包：
./tools/unity/build-reference-look.ps1 -SkipModels -BuildWeChat
```

脚本使用本机固定的 Blender、Python、Unity 和 Node；路径变化需同步脚本。Windows PowerShell 入口使用 UTF-8 BOM，后台进程隐藏窗口并检查真实退出码。

| 步骤 | 工具 | 输入与产出 |
| --- | --- | --- |
| 提取材质映射 | `prepare_reference_materials.py` | 从当前主题和参考关筛选源 `source.json`／`.blend`，保留源浮点、颜色、纹理绑定及来源 SHA-256 |
| 几何迁移 | `build_reference_materials.py` | 原 UV／法线、单位归一化、原材质分组；输出 Blend／FBX／GLB 和逐模型预算 |
| 双重校验 | `validate_reference_look.mjs` | Blender GLB 回读面数／尺寸与 Khronos glTF Validator；拒绝额外材质分组、错误、警告和超预算 |
| 安全接入 | `stage_reference_look.py` | 校验候选 FBX／GLB／材质 JSON／纹理哈希；保留原 FBX GUID；生成运行预算表 |
| Unity 材质修复 | `GooseReferenceMaterialImport` | 绑定源纹理与参数，显式修正已有贴图导入设置；增量执行无须每次全部重导 |
| 实际渲染预览 | `GooseLookAcceptance` | 强制移动档，80 件四视图、192／64 图标；同一暂停物堆的三种渲染对照 |
| 图标入库 | `stage_reference_icons.py` | 只接受完整通过的 Unity 实际渲染预览，保留图标 GUID；鳄鱼、恐龙、彩泥选择更可辨认的正面 |
| 导入审计 | `GooseReferenceImportAudit.Run` | 检查 UV／法线、102 个材质的实际纹理绑定、颜色／数据空间、分辨率、mip 与 Shader 编译 |
| 构建 | `GooseDeviceBuild.ReferenceLook`／微信构建脚本 | 本地独立开发包及当前小游戏完整资源／Wasm 包 |

候选目录为 `source-assets/models/candidates/reference-look-20261025/`。原资源备份在 `projects/catch-big-goose-unity/SourceAssets/ReferenceLookBaseline-20261025/`，不会混入运行时 Resources。几何文件的 `.meta` 保留，清理过时的 FBX 材质重映射；生成新资源前不删除原模型。

首次微信完整导出为 32,320,316 字节，超出 30 MiB。检查发现已被市集 UI 替换的 `Textures/challenge-ui/` 仍随 Resources 打包；确认当前 C# 与场景无路径／GUID 引用后，将该旧目录及 `.meta` 原样移到 `SourceAssets/ReferenceLookBaseline-20261025/retired-ui/`，记录逐文件哈希。此项只排除未使用的旧 UI，没有缩小源材质贴图、删减当前模型或裁掉奖励短片。工具 `retire_reference_legacy_ui.py` 为可重复执行的归档步骤。

## 3. 贴图和颜色迁移

**【确认·项目适配】** 基础色和 MatCap 用 sRGB；AO／MatCap 分区遮罩用线性数据采样，文件名前缀分别为 `t_`／`d_`。同一原图若承担不同采样用途，可保留两份导入配置。最大导入边长 1024，启用 mip，保留原图，不再把水机多个 512² 材质压进同一 512² 小图集。1024 是允许上限，不会把 128² 贴图插值放大为新细节。

已有 `.meta` 不会仅因修改预处理代码自动变成新参数。本轮专门增加幂等导入修复，实际检查已有纹理的 max size／mip／sRGB／wrap，避免“代码写了 1024，构建仍用 512”。源颜色和 MatCap 原浮点权重保存在材质 JSON，颜色向量避免额外的 Inspector 颜色转换。

## 4. 实际光照与材质公式

以下均为 **【项目适配】**，与第 23 章冻结包内方向光 0.38 等源字段分开。

- 不透明材质使用 `Goose/ReferenceOpaque`：片元阶段归一化法线，基础漫反射范围由 `smoothstep(-0.15,0.85,N·L)` 控制；固定填光 0.38，主光项系数 0.62。源 `_LightColor` 按本项目归一化映射，源值为零时保留基础漫反射关闭的语义。
- MatCap 根据视空间法线 XY 映射到纹理；源纹理、颜色、强度保留，但加法增益 2、双分区 RG 组合及底层权重是本项目近似，未恢复原程序。
- 仅有源 AO 输入且权重大于零的材质启用 AO 变体，影响基础色项；不等于恢复原 AO 对高光、阴影等各分支的完整作用。
- 玻璃使用 `Goose/ReferenceGlass` 独立透明层，剔除背面（Cull Back）、ZWrite Off、普通 alpha 混合；源 alpha 经限制，加边缘项。没有 GrabPass、折射、动态反射或原晶体完整公式。
- 当前测试场景统一中性白方向光，强度 0.8，硬阴影强度 0.45、距离 32、单级联、Medium 阴影分辨率；默认阴影开启，可在暂停菜单关闭。它们是测试配置，不是竞品当前运行值。

使用源材质的模型在微信／移动档不再被替换成旧 `GooseItemMobile`。不透明层可投射／接收阴影，玻璃不投射；拾取到 UI 相机层的物件关闭投射，返回场景再恢复。容器动态材质在退出时释放，对照状态及光照设置退出后恢复。

## 5. 测试场景与真机对照入口

首页“对照”弹窗显示 **材质版本 R3**。保留玩具 **126／300 件**测试关；当前五个参考主题也自动使用本轮材质与光照。暂停进入“关卡画面设置”可以切换：

1. 材质迁移／基础色对照：在同一堆物件上去掉 MatCap、透明混合和阴影，比较塑形差异。两档几何均为本轮分组，并非整个 R2 包回滚。
2. 接触阴影开／关：比较物件遮挡层次与额外投射开销。默认单盏有限阴影，没有加入屏幕空间 AO 或后处理链。
3. 标准／高清：微信中调用已接入 SDK 的 `SetDevicePixelRatio`，请求 1.5／2。保留默认 1.5，没有直接全局升到 3。

**【待确认】** SDK 调用已编译，不代表该 iPhone 的画布尺寸、触摸映射、切档是否立即生效已经验收。应同时查看性能行中的真实宽高；DPR=2 相比 1.5 的理论像素数量约 1.78 倍，帧率变化须实测。透明排序、阴影锯齿和物堆重叠也需在微信 WebGL 实际图形后端确认。

## 6. 验证和证据

验证报告、实际运行截图、候选哈希、导入审计、源参数、源码快照和新微信包清单保存在[本轮证据目录](../../competitor-analysis/evidence/2026-10-25-材质模型光照迁移/验证汇总.json)。同堆画面对照、80 件图标总览和早茶等关卡截图直接取自 Unity 强制移动档，未使用生图替代运行效果。

最终通过：80 件 GLB 回读／Khronos 校验，102 个材质导入绑定，320 张四视图与 160 张图标，22 项编辑测试，132 项算法回归，60 项交互验收，7 个占屏／越界场景，五主题 15 局及玩具 126／300 件两局可见策略样本全部通关。脚本样本不等于人工或竞品胜率。微信已完成真实 GLES3 Shader 和 WebGL／Wasm 编译、SDK 转换；本地导出 **26,075,630 字节（24.87 MiB）**，61 个 JS 语法、两支完整短片及字体哈希通过审计，仍不等于手机帧率验收。

微信开发者工具已成功打开新包，CLI 本次真实返回 `√ preview`，生成[本轮 R3 预览二维码](../../competitor-analysis/evidence/2026-10-25-材质模型光照迁移/wechat/wechat-r3-preview.png)。平台给出的打包大小为 **25,429,254 字节，界面显示 24.3 MB**，其中主包 1,708,730 字节。这个平台预览大小与上面的本地原始文件合计口径不同；成功生成预览码仍不是 iPhone 运行／帧率证据。二维码可能失效，届时在已打开的当前工程重新“预览”，确认首页 R3。

可重复执行 `python tools/unity/verify_reference_look.py`，核对冻结证据、原输入、当前实现、实际原生开发包和微信导出逐文件哈希；本轮快照不会覆盖 R1／R2 历史证据。

验收结果以该目录最终汇总为准，原型阶段 21 件测试以及失败后修复的中间日志保留在 `work/reference-look-20261025/`，不与最终 80 件结果混计。算法历史 81 件夹具需要 9 类，杂货实际只有 7 类，因此仅在开发验收临时补足真实物件 ID，再恢复实际主题后验证生产核心档；生产配置和类型权重未因此改动。

本地开发包功能通过不等于手机性能通过；原版 Shader 全部关键字、色相迁移、世界 MatCap、玻璃光学公式、当前账号热更后的最终灯光，以及 iPhone 15 Pro 的 GPU／P95／实际画布仍是 **【推测／待确认】**。未连接手机，因此本章不宣称持续卡顿已解决或画面已经像素级复刻。
