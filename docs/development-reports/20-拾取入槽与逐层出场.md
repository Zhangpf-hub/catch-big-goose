# 20　拾取入槽与逐层出场

R1 后续：保留本章实际动画路径和自底逐层出场；完成出场后改为立即恢复深度管理，普通移除改为局部唤醒且保留原可见状态，并加入材质合并／接触网格／30 Hz 移动物理适配。当前源码、最新 60 项交互回归与手机测试入口见[第 21 章](21-iPhone持续卡顿与玩具对照.md)；本章冻结哈希仅对应本章历史版本。

日期：2026-10-24。针对“点击物件瞬移进栏、开局从高处倾倒”的体验差距。延续第 15 章核心算法和第 17 章资源缓存／对象池，不覆盖第 18、19 章的界面设计。

## 一、证据范围

**【确认·静态／资源】**本轮读取本地 402 版的两个 WASM、IL2CPP 元数据，以及同一冻结包的 `sharedassets0.assets`。新增证据放在[本轮证据目录](../../competitor-analysis/evidence/2026-10-24-拾取与逐层出场/验证汇总.json)。没有登录竞品账号，没有取得其当前线上热更后的完整动画录屏。

资源读取使用 DummyDll 生成字段布局，修正 MonoBehaviour 内置头的字节对齐，启用严格总字节数检查，并比较生成布局与原生读取的 `m_Script` 指针。实际引用链为：

```text
LevelManager._newAnimManager → pathID 962
LevelObjAnimManager._config → pathID 772
ObjAnimConfig / ObjectAnimConfig3
```

这比只读取字段声明、构造函数默认值更强，但仍不能证明任何账号运行中均未覆盖这些值。

## 二、竞品拾取调用链

**【确认·静态】**恢复出的核心链为：

```text
LevelManager.GetUnit
 ├─ ObjectUnit.BeClick：结束物理参与、处理拾取状态和缩放
 └─ CanUseNewAnim
     ├─ true → LevelObjAnimManager.ClickObj → DelayToCheckContent
     │          ├─ XZ 位移、Y 位移／抬升、旋转、缩放分别建立 Tween
     │          └─ 到位后检查组合 → CombieObj → CombieAnim
     │                                      └─ 移动／缩放 → LevelObjectPool.Recycle
     └─ false → RefreshContentDisplay → 旧动画检查链
```

对应方法：`GetUnit $j14621`、`CanUseNewAnim $j6451`、`ClickObj $j43500`、`SortContentObj $j10875`、`DelayToCheckContent.MoveNext $j74326`、`CombieAnim.MoveNext $j74405`。直接调用图仅证明语法调用边；上图的分流结合具体分支读取。

`GetUnit` 返回 Vector3，原 Dumper 的简化签名与 WASM 直接签名不同。本轮只对声明明确为 `UnityEngine_Vector3_o`、且完全符合“void 返回＋前置返回缓冲指针”的方法启用显式 ABI 适配；原始签名和适配原因均保存在方法映射。其余签名不匹配、未展开的重定向仍拒绝解释。

`CanUseNewAnim` 检查 `IsUseNewAnimManager && !HasTwoPlayer()`；静态初始化将该开关设为 true。**不能据此称双人模式使用相同新动画，也不能据静态初始值证明账号运行时始终开启。**

## 四、竞品由下至上的创建依据

**【确认·静态】**`CreateInfo.pos` 位于偏移 0xC，故 `pos.y` 位于 0x10。`LoopCreateObj` 两个排序委托共用 `$j13265`：读取两个记录偏移 16 的 float 并调用 `Single.CompareTo`；协程内确实把该委托传给 `List<CreateInfo>.Sort`。这支持相关分支按生成位置 Y 升序创建，不能只根据方法名字推断。

**【确认·资源】**场景还保存：常规创建时长 2 秒、每批 3 件、最大间隔 .03 秒、增长速度 .10；物理创建分支为 3.5 秒、每批 3 件、最大间隔 .04 秒、增长速度 .20。`ObjectUnit.FinishCreate` 和 `LoopCrowObjSize` 支持创建完成与缩放生长的处理。

**【边界】**排序代码存在模式分支，另有按物品名称排序路径。不能将“Y 升序”外推到所有活动和双人模式。`ShowCreateAnimMod` 是另一个通用展示组件，不能因为名称相似就当成核心物堆的完整出场算法。

## 五、Unity 接入

以下全部属于 **【项目适配】**，不是逐行恢复的竞品源码。

### 5.1 真实 3D 物件飞入

`GooseTrayPresentation` 接管点选后的原模型，不销毁再换图标。转换前后保持投影中心和初始投影尺寸，关闭物堆碰撞参与；独立相机使模型可以跨过游戏视口边缘到达七格栏。常驻槽内／暂存区仍显示原 3D 模型。

普通拾取可连续点选，立即预留逻辑槽位，同类插入时邻居从当前位置平滑移动。正在飞入的对象更换目标时也从当前位置重新衔接。三消期间暂停冲突操作，等待飞入／落位完成后聚拢缩放，再更新消除数、回收到池中和判断胜利。满七格失败也等待最后一件到位；第七件恰好凑三消优先消除。

时间范围、UI 横纵距离权重、正弦位移和 .20 秒重排参考上表。项目 UI 基准为 720，抬升投影、槽内朝向、正弦放大、落位轻弹，以及三消聚拢／缩至零的轮廓为自有实现，**未复原竞品完整 3D 路径、全部缩放曲线和粒子效果**。

对话框／提示使用更上层的 Canvas，避免飞行模型遮盖暂停与结算。没有新增逐物件 RenderTexture，也没有复制模型网格或逐帧创建材质。

### 5.2 从稳定底层逐层长出

保留有限库存、权重、预算层和目标鹅数量。先用已烘焙碰撞体在底部寻找无重叠承托位置，创建和布置继续受分帧预算控制。隐藏模型时进行最多 2.2 秒的物理稳定，随后冻结承托位置，按实际 Y 升序分高度带显示并做 .28 秒生长。上一高度带已有生长进度后再显示下一带；显示结束才开放点击并开始计时。

隐藏稳定阶段用于消除 AABB 安全摆放产生的高柱，避免“先在高处长出，最后又一起掉落”。该阶段可能增加准备时间，不能把本次效果改动宣传为冷启动提速。

显示完成后恢复正常刚体和原深度管理。源配置预算层 `GenerationLayer` 与几何展示高度带是两种概念；本轮没有重分配各层库存。原 `sourceHeight` 保留在核心配置中，**不再直接作为从高处投放的出生 Y 坐标**；本地承托形状和空间尺度仍为项目适配。

### 5.3 生命周期和回归边界

暂停停止飞行；重开／返回首页清理正在飞行的表现状态，回收前恢复原缩放和渲染层。移出道具将已有模型滑向暂存区，暂存点选走相同飞入流程。磁铁也使用生产动画。

历史纯算法验收显式开启仅开发版可用的即时拾取开关，以继续验证库存／配额规则；它不能作为动画通过证据。新交互验收和可见单局策略均关闭该开关，走实际动画。

## 六、验证结果

实际报告、源码快照、构建日志、界面截图和微信包检查见[本轮验证汇总](../../competitor-analysis/evidence/2026-10-24-拾取与逐层出场/验证汇总.json)。本轮 Unity 编辑测试 18/18、交互验收 60 项、算法回归 132 项通过；生产动画路径的可见策略完整单局 20/20 通关，失效点击和掉出库存均为 0。这是自有自动策略，不代表人工或竞品胜率。微信 Release 本地包检查通过，原始文件总量 27.90 MiB；模拟器和手机仍未验证。

另按五主题分别冷／重复开局完成 10 组独立桌面移动档采样，库存均为 300、掉出均为 0。完整准备＋出场平均冷 10.48 秒、重复 7.94 秒；最长采样帧 49.98 ms。该结果不是手机 FPS，也不能直接与并行构建时的数据比较。层序呈现与隐藏稳定使准备／出场等待增加，未把它计作加载提速。

首轮验证暴露的两处问题已修正：预布置阶段的 Rigidbody 插值改为关闭，并同步刚体姿态，防止排序位置被插值覆盖；暂停时表现更新立即返回，防止暂停当帧再移动一步。另对只安全摆放后直接揭示的版本增加了隐藏稳定阶段，避免揭示后继续高空下落。

## 七、推测与待确认

- **【推测／待确认】**账号 AB、热更是否改写新动画开关或 ObjectAnimConfig3；本轮只证明冻结包初始配置和分支。
- **【推测／待确认】**竞品真实触屏的连续输入节流、触觉反馈、粒子与相机合成参数，仍需同版本完整录屏／运行采样。
- **【待验证·项目】**微信开发者工具当前导出包运行、真机 GPU／CPU 帧耗和内存。本地 Windows 移动档与静态包检查不能替代这些测量。
