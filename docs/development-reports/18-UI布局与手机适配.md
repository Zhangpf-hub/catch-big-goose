## 竞品依据与规格边界

以本仓库保存的真实《抓大鹅》烧烤画面为主要布局依据：`reference-projects/competitor-goose/2026-10-22/evidence/01-barbecue-initial.png`。其中右侧游戏客户区约为 447×795，接近 9:16；这是截图观察尺寸，**不是确认的竞品 Canvas 设计分辨率**。公开产品页面：[蓝飞互娱](https://www.kunpo.cc/games/zhuadae.html)、[App Store](https://apps.apple.com/cn/app/id6475341440)。官网搜索结果可检索，但本轮直接请求返回 502，未以其页面内容冒充实测。

画面结构：左上暂停，中央大面积场景与物件，底部七个浅灰色槽位，最下面三个亮黄色立体道具按钮。截图中槽位约占客户区高度 10%，道具区约占 11%；这些是当前样本的近似测量，不代表所有模式。美术使用粗描边、白色/奶油色文字底板、黄色强调色、饱满的道具图形。已有观察详见第 02 章和原证据报告。

本轮重做对应的视觉层级与对局结构。首页保留项目已有五个主题和三档难度，使用原创鹅插画与浅蓝底卡片网格；不声称首页流程与竞品逐项相同。

## 自有实现规格

| 项目 | 本轮实现 |
| --- | --- |
| 布局坐标 | 逻辑宽 720；高度按安全区域宽高比计算，取消固定 1280 高度约束 |
| 宽屏/平板 | 居中竖屏区域，宽度不超过安全高度的 0.625 倍 |
| 顶栏 | 相对安全区顶部布局；暂停、倒计时、关卡、得分、进度 |
| 底栏 | 7 格，各 88×88；三个 158×112 道具按钮；独立暂存栏 |
| 可点击尺寸 | 最小手机样本上主要按钮约 44 像素高；逻辑高度最低 88 的暂停/声音/难度/弹窗按钮 |
| 物件区 | 使用与 UI 同一安全区域计算相机 pixelRect；保留上下栏空间，按宽高比计算正交相机尺寸 |
| 输入 | 仅相机可见区域接受物件拾取；UI 仍由 GraphicRaycaster 处理 |
| 系统区域 | Unity Screen.safeArea；微信初始化后采用 SDK safeArea，额外预留右上胶囊下沿 8 个 CSS 像素；监听窗口变化 |
| 视觉 | 浅蓝、奶油白、亮黄，深蓝灰轮廓；原生圆角卡片、阴影、可缩放道具图形 |
| 字体 | 原 OFL 中文字体重新按当前文案子集化；道具名称仍用已烘焙透明文字贴图 |

代码：`GooseHud.cs`、`GoosePhoneLayout.cs`、`GooseToolIcon.cs`、`GooseWeChatPlatform.cs`、`GooseGame.cs`、`GooseVideo.cs`。
