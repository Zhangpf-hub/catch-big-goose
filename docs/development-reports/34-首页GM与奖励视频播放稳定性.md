# 首页、GM 与奖励视频播放稳定性

日期：2026-10-25。版本：`20261025-UI5`。Unity：2022.3.62f3。

## 首页与设置

去掉首页标题下的「三个就消除」、开始按钮上方的三消提示及其空白底条。首次进入直接打开首页，规则通过「玩法」按钮按需查看。保留主题与「开始关卡」，简单热身自动衔接正式挑战的流程不变。

设置新增可保存的「GM 无限次数」开关，默认关闭。开启后，真实剩余次数为零也能进入并连续挑战，且不扣除、不伪造真实次数；关闭后立即恢复原来的次数限制。移除设置中的「画面与性能对照」按钮和对应弹窗入口；设置只显示音乐音效、GM 和返回市集。

## 点击观看短片后立即退出的排查

用户确认退出发生在点击「观看短片」之后立即发生，没有先正常播放。此次没有取得对应手机的原生崩溃栈，因此不能断言具体是内存不足、图形驱动还是解码器错误。

旧链路在点击时直接创建 Unity VideoPlayer 与 1280×720 RenderTexture；媒体分包缓存还会把整段 MP4 读入 JavaScript ArrayBuffer 后再写入用户目录。首页模型预加载在游戏未进入 Playing 时也不会因 Paused 自动停下。这些操作均处于崩溃触发点附近，是本轮明确收敛的资源风险。

微信端改为原生 `wx.createVideo` 视频层，不创建 Unity VideoPlayer 或视频纹理。原生视频接口与事件字段参照[当前 SDK 的 Video 适配器](../../projects/catch-big-goose-unity/Packages/com.qq.weixin.minigame/Runtime/wechat-default/unity-sdk/video.js)。两支原有完整短片及奖励内容保留。

- 缓存改用原生文件复制，不再把 MP4 整段读入 JS；已有缓存先校验字节数，残缺缓存重新复制。
- 监听播放、进度、结束、暂停、错误；只有实际播放、收到进度并自然结束才发奖。失败、加载超时、关闭或切后台不发奖。
- 每次播放使用独立请求编号，关闭后立即使旧回调失效；旧会话不能关闭新视频或重复发奖。
- 播放器销毁移到事件回调栈之外，避免在自己的 ended/error 回调中同步销毁原生对象。回调方法显式保留，供 IL2CPP 的 JS 消息调用。
- 视频期间暂停模型预加载并暂时关闭非 UI 的 3D 相机；结束后恢复原暂停和渲染状态。
- 桌面保留真实 VideoPlayer 播放作为回归路径，纹理缩为 854×480；停止前先解除目标纹理，使用帧末销毁代替结束回调中的同步纹理释放。

## 验证与范围

播放器回归覆盖零次数限制、设置切换 GM、零次数连续三次进入难关、不篡改次数、关闭 GM 恢复限制、实际增加次数入口、完整播放两支短片、七次取消／快速关闭、每次仅回调一次、取消不发奖、解码器和纹理释放、预加载暂停及暂停状态恢复。微信桥接检查覆盖原生文件复制、缓存、失败处理、自然结束、旧回调隔离、重复结束、快速重开和不支持接口时的错误返回。

这些检查验证了代码、桌面真实解码及微信接口协议；点击即退出的问题仍须使用本轮新预览在原手机复测，不能将桌面或模拟接口结果写成 iPhone 已修复。

最终结果：37 项编辑测试通过；63 项真实播放器检查通过，包括完整播放 2 次、取消 7 次；文件缓存与原生视频生命周期共 15 项协议检查通过。Windows QA 保留本机 PlayerConnection 配置，没有请求防火墙授权。微信完整 WebGL 编译和导出通过，本地包约 28.08 MiB，15 项包审计及 61 个 JS 语法检查通过，预览上传 28,788,439 字节。命名明确的 Windows／微信运行入口均已更新，并与固定交付包核对。
