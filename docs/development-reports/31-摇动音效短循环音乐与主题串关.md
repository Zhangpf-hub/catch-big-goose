# 摇动音效、短循环音乐与主题串关

日期：2026-10-25。流程／音频版本：`20261025-UI4`；基于当前 Unity 2022.3.62f3 工程及构建时的 PERF1 基础。

## 玩家流程

首页仅保留主题类型和「开始关卡」，去掉第一关／第二关、解锁及数量／时长选择。每次从首页开始都先进入 15 件、不限时的简单热身；完成真实消除后，等待 0.7 秒自动进入同主题的 300 件挑战，不出现「挑战第二关」按钮。对局状态与结算均显示主题名称，不显示关卡序号。

主题通关记录继续保存，但不再用旧的阶段选择存档跳过热身。进入挑战只扣一次既有挑战次数，热身不扣；难关失败重试保留难关，不重复扣次。返回首页会取消待执行的自动衔接，下次开始重新热身。保留暂停、短片补充次数及成绩记录。

## 摇动声音

上一版虽有播放调用，但短声峰值与播放增益均较低，很容易被音乐盖住。此次提取已有竞品缓存中的 `S_ToolShake`，作为用户要求的本地原音对照。来源、编码、时长与证据边界见[竞品音效记录](../../competitor-analysis/18-摇动音效与短循环音乐对照.md)。

音效改由独立的二维 AudioSource 播放，优先级 32；每次接受摇动触发四个强弱变化的短声，覆盖物件翻动。摇动期间背景音乐降到正常音量的 40%，之后恢复。声音开关同时控制音乐与摇动；新存档默认开启，已有明确关闭的设置仍保留。

实际播放器通过 Audio DSP 回调录得非静音输出：106,496 个采样值，RMS 约 0.0587。该录音验证真实播放器音效输出，不是单凭“调用过播放函数”作判断。它不替代手机扬声器听感验证。

## 背景音乐

新音乐为原创合成：140 BPM、约 13.7 秒循环；同一个两小节短句反复出现，使用短促橡皮感音色、切分低音、四拍底鼓和反拍打击。取消上一版较长的旋律发展与铺底，让节奏成为主体。工具为 `tools/unity/prepare_rhythm_audio.py`，音频审计、试听和源哈希位于 `work/rhythm-flow-20261025/audio`。

## 验收

37 项编辑模式测试通过；真实播放器 534 项流程、UI、音频检查通过，覆盖四种首页尺寸、五主题简单关真实清空后自动进入难关、旧通关存档、次数扣除、难关重试、回首页取消衔接、重开从热身进入、音频 DSP 非静音、连续短声、音乐压低／恢复及静音开关。

为避免与并行性能调优互相占用工程，构建使用 `work/rhythm-flow-20261025/build-workspace` 中的固定源码快照；主工程内的本轮实现保持可编辑，并行性能源文件不回滚。后续性能版本不应直接套用本轮快照的完整验收结论。

Windows 默认运行入口和命名明确的微信导出入口均已更新，并与验证包逐文件核对。微信包本地约 28.10 MiB，15 项审计、61 个 JS 语法检查通过；预览上传 28,812,017 字节。旧运行包完整保留在本批次 `previous-windows`、`previous-wechat`，未删除旧资源。

目录检查在交付前通过 43 项；最后复核时，并行性能聊天的另一次导出替换失败，留下 SDK 内部 `minigame` 中间目录，使该轮目录检查报一项未发布错误。未移动或删除其待处理输出。本轮 UI4 命名导出目录及固定预览包的完整性验证通过；预览生成后已关闭临时开发者工具服务，释放共享导出目录的占用。
