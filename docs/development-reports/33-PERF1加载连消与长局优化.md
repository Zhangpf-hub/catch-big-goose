# PERF1 加载、连续消除与300件长局优化

2026-10-25。基于当前 Unity 2022.3.62f3 工程，保留五个主题、各自背景及现有热身衔接挑战流程。保留用户已经确认的 SHAKE2 翻堆效果。本轮实机性能仍由用户扫码复测，不把 Windows 或微信开发者工具的帧率当成手机结果。

## 变更

原来的场景准备会逐个等待模型／凸包加载，创建300件后再运行最多300步高精度物理模拟，材质预热还会每类固定等待一帧。现在把十个默认关卡的已验证初始堆形保存为布局资源；运行时核对关卡库存／种子、容器、重力／常态摩擦、模型规范化尺寸、实际凸包顶点、物件尺度和完整库存，匹配才使用。不同种子或不兼容配置仍走原实时准备流程。本轮25组摇动回归同时验证了替代种子确实回退，未把布局用于不匹配的关卡。

这只复用开局姿态。物品在出场结束后仍交给原来的动态物理、深度管理、收拢和摇动逻辑，并没有在游玩期间固定整堆。复用时保留层级配额和每件尺度；热身中可以继续在隔离物理场景里准备下一场挑战。

资源加载改成四个模型的小批并发窗口，移动档使用低优先级资源集成；创建和材质预热按时间预算让出帧，音效也进入实际使用的缓存。出场改为一条底部向上的动画队列，约0.65秒依高度出现，加约0.2秒弹出完成，替代300个独立弹出协程和原1.2秒铺开加0.25秒收尾。

连续拾取改用可复用碰撞查询缓冲，并只选最近五个碰撞体，去掉每次分配完整碰撞数组、排序全部结果的路径；Renderer查询也复用缓存。槽中已落定的模型不再逐帧重设位置、旋转和缩放，布局变化时仍重新定位。三消继续即时预留逻辑槽位、独立提交动画，避免锁住后续拾取。睡眠堆降低重复深度／遮挡刷新频率，取走、摇动或收拢唤醒时立即失效重算；稳定后的临时高求解设置恢复正常档位。底面保护仍覆盖活动物件，收拢尺寸及画质参数没有降低。

摇动的 `ApplyPulse` 实现与 `interaction-r4.json` 参数均与改动前逐字节核对一致，包括五段脉冲、力度、旋转、摩擦、冷却和64件施力上限。只增加中途返回／重开时的取消清理：在物件入池前恢复临时材质、清除旧请求和冷却，防止旧翻堆状态进入下一局。

## 加载对照

下面均为 Windows 450×844 开发包强制30 Hz移动档。准备时间从本次场景准备请求计到 Ready，出场时间从准备完成后采用场景计到可操作。它们**不是从点击微信图标开始的总冷启动时间**，也不包含首次下载及微信／Unity引擎初始化。

| 300件主题 | 原准备 | 新准备 | 新出场至可操作 |
| --- | ---: | ---: | ---: |
| 早餐 | 8,788 ms | 325 ms | 898 ms |
| 烧烤 | 8,889 ms | 223 ms | 897 ms |
| 乡村 | 8,889 ms | 224 ms | 894 ms |
| 玩具 | 10,157 ms | 256 ms | 894 ms |
| 杂货 | 9,156 ms | 256 ms | 893 ms |

五主题准备中位数为 **8,889→256 ms**；准备后的出场中位数 **1,498→894 ms**。测试中从场景准备请求到可操作的中位数为10,425→1,159 ms。默认十关全部命中布局缓存，五个热身关均验证了后台准备300件挑战；每主题额外验证摇动中退出后，重开恢复300件、材质和输入状态。

微信开发者工具实际触控通过早餐热身，完成15/15后自动衔接300件挑战；两段都命中缓存。模拟器热身首次准备约2,089 ms、准备后出场约1,036 ms；300件后台准备约3,244 ms、准备后出场约927 ms。模拟器资源集成和GPU预热仍有成本，不把原生256 ms替换成微信端耗时。之前模拟器300件准备约19.6秒的记录保留于第27章，非严格同次冷启动对照。

## 连续消除与长局

- 编辑模式测试37项通过；生产交互专项60项通过。
- SHAKE2摇动回归25组、1,680项通过，包含五主题15件／300件及收拢剩18件场景，未削弱翻堆参数。
- 最终长测554项通过：五主题各在300件库存下运行6秒静置、六次摇动、再60秒持续运行并每8秒摇动，然后各进行72次连续拾取、独立三消提交、暂停恢复、摇动中退出及重开。
- 最终20个采样阶段共413.03秒、12,388帧；本机该样本没有超过50 ms的帧。这是30 FPS封顶的本地结果，不是已验证手机稳30 FPS，也不据此承诺所有机型帧率提升比例。
- 60秒持续阶段结束时，五主题托管内存快照约3.2～4.5 MiB，Unity分配快照约59.4～68.5 MiB；不同主题的模型预算不同。它们不是手机进程／GPU的总内存或逐帧峰值，也不足以宣称长期绝无泄漏。
- 当前Mono的每线程分配计数接口始终返回0，已经明确记为不可用，没有把这个0写成“零分配”结论。GC次数和内存快照分别保留在原始结果里。
- 当前热身衔接、菜单和摇动音效的相关回归534项通过，保留其他任务已完成的流程和音效。

最初长测在普通协程恢复时做底面断言，有一项失败；其发生在 LateUpdate 的底面保护之前，未记录具体穿透值，因此没有据此直接断言是物理错误或仅为测量错误。补充显示前／显示后／刚体姿态三个读数，并把最终断言放到实际渲染帧结束后。单主题复查和完整五主题复测均通过；最终显示姿态和刚体凸包最低Y均不低于0.020，保留首轮失败文件，不通过降低阈值消除失败。连续摇动期间的逐帧防穿底／边界检测另由25组专项覆盖。

## 微信包与预览

最终包28.10 MiB，15项本地包审计、61个JavaScript语法检查、7项媒体桥检查及43项目录检查通过。CLI返回 `√ preview`，实际上传28,811,644字节。曾遇到共享常规目录被其他构建更新，以及开发者工具继续使用旧文件索引的问题；旧二维码单独保留、不作为交付。最终上传的两个分包大小与当前文件及冻结包逐项核对一致：

- WASM：`3a2766dc3728db69`，压缩文件4,450,352字节；SHA-256 `ea641579d8931759552f1bab7b661e805c38bbdc5ed542b2ea29cfb1b14329c2`。
- 数据：`b9966cb7e74e5e8d`，压缩文件17,487,198字节；SHA-256 `e78cd384208a78f697adbc0377d7aa77dba64ce16f2bd74a58d986ed0353356b`。

SDK在改名替换被占用目录时失败后，使用完整旧包备份、受限路径的逐文件发布恢复；原SDK导出目录归档到 `completed-sdk-export`，不遗留第二个入口。前述Windows弹窗遮挡现已解除，实际模拟器已完成本轮触控与PERF1缓存确认；本轮没有操作防火墙许可或后台隐私配置。Windows测试网络连接修复另见第32章。
