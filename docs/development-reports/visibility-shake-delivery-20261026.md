## 原因与实现

下层闪烁来自遮挡状态的循环依赖：原遮挡者资格读取其他物品的当前 `DepthVisible`，计算结果又改变该状态。现在在一个几何/相机快照内按前后顺序分类，只使用已确认的前方计划结果；显示可及时发布，隐藏必须等完整有效分类结束后提交。静止后不重复轮询，移除、相机、物品姿态或材质资格变化才触发重算。

为避免隐藏仍有边缘露出的物件，缓存开场缩放之前的完整作者渲染包围盒，使用整个投影范围采样；遮挡必须位于该范围的最近深度之前。透明材质、未知材质以及不确定的查询保留显示。物理凸包只取收缩后的内部作为覆盖依据，并保留每次刷新最多 256 次查询。渲染决定与下层 kinematic、无重力的碰撞支撑独立。

微信监听原先在热身结束和挑战准备时停止再启动；异步 Stop 完成可能落在新 Start 之后。现在跨正常自动转关保留同一监听流，输入控制器仍在新物品准备完成前拒绝摇动。真正暂停、回首页、切后台时停止监听；后续启动等待 Stop 的 complete 回调，旧代次回调不能驱动新局。

快速暂停→恢复→再次暂停共用一个正在等待的 Stop；Stop 完成也绑定独立代次，旧 complete 不能释放更新一次 Stop 的等待门禁。实际源码方法块在 PowerShell 7 的受控异步 SDK mock 下通过 7 个场景：上述快速切换、Stop 失败完成、过期 complete、真实转关意图、旧监听回调、过期 Start 成功及三次有界失败重试。该测试不伪称真实微信传感器成功，微信包已据同一最新监听源码完整重编。

表层沿用当前已实现的受控颠锅：仅操作手势接受时原已激活可见集合，抛起、横向弧线、翻转并落稳换位，不解冻下层、不消耗打乱道具。竞品冻结代码证明显示/物理分开及动态物品摇动资格；当前受控轨迹是本项目适配，不能称为逐行还原竞品手机物理。证据依据见[竞品表层激活研究](../../competitor-analysis/normal-mode-surface-activation-20261026.md)。
