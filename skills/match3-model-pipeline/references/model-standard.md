# 模型生成规范（依据本项目 2026-10-21 资源与源码）

## 项目既有约定

实际工程 Cocos Creator 3.8.8。可玩模型来自 `reference-projects/catch-big-goose-cocos/assets/resources/models/<id>.glb`，图标为 `resources/icons/<id>.png`。`PrefabCache.ts` 优先尝试 `models/<id>/<id>`，再尝试 `models/<id>`；`ModelManifest.ts` 只提供历史兜底 UUID，不应为了新增模型随意补写。

`tools/art/gen_farm_theme.py` 与 `prepare_generated_model.py` 规定几何包围盒居中、最大边 1.0；Blender 是 Z-up，glTF 导出 `export_yup=True` 后变为 Y-up。建模时产品正面朝 Blender -Y，导出后朝 glTF +Z；屏幕向上的平放设备，其屏幕法线由 Blender +Z 映射成 glTF +Y。不能把 Blender 和游戏的朝向混用。

`GameManager.centerVisualAndMakeShape` 会按实例尺寸居中，`JoltWorld.extractHullPoints` 将各子网格变换到 root 局部坐标，按 12×12 方向桶取极值点。动态件使用凸包和 0.01 的凸半径，开启 CCD。耳机孔洞会被凸包填实，这是物理近似，不能承诺耳机按内孔互相穿套。

现有 GLB 的材质数、尺寸和面数存在历史例外。审计生成的 `asset-audit.json` 的 baseline 列出全部现有模型，容器与普通件应分开评估。高面数历史资源不是新资源默认预算；未要求时不批量重制。

## 新普通物件的批次预算（新增约束）

| 项目 | 默认目标 / 交付门禁 |
| --- | --- |
| 标识 | 小写 ASCII id，文件与根 mesh 同名；无品牌、商标或真实 UI 复制 |
| 尺寸 | GLB 世界坐标最大边 1.0 ± 0.0001，包围盒中心各轴绝对值 ≤ 0.0001 |
| 厚度 | 最大边归一后最短边 ≥ 0.08；手机也需具备实际厚度 |
| 三角形 | 目标 1,000–4,000；上限 6,000，以三角化后的 GLB 为准 |
| 材质 / draw calls | 本电子产品批次一个材质、一个 primitive、一个 mesh；复杂新物件可另定预算 |
| 贴图 | 本批 64×64 配色图集，内嵌 PNG；通用默认 ≤256×256，例外需说明 |
| 材质模型 | 标准 PBR metallic=0、roughness 0.45–0.75；OPAQUE、背面剔除 |
| 扩展 | 本批不使用材质扩展、不依赖 Draco / Meshopt / KTX2，不要引入额外解码运行库 |
| 单件体积 | ≤256 KiB GLB，图标另计；发布仍服从项目总体资源门禁 |
| 图标 | 192×192 RGBA，正交三分之四视角，四边透明留白至少 6px，另验 64px |
| 几何 | 实体部件闭合；回读后临时按 1e-6 焊接检查无开边、无退化三角形与非有限坐标 |
| 内容 | 一个可拾取物件，无地板、灯光、相机、动画、骨骼或多余复制实体 |

配色图集按每个部件的 UV 指向相应色块中心；显式 `ShaderNodeUVMap` 接到纹理，避免已有脚本记录的 `texCoord=-1` 问题。不要把调色贴图与金属粗糙度图混淆。

部件允许真实装配中的交叠和独立闭合壳体；“一个物品”不等于“强制只留最大连通块”。`prepare_generated_model.py --keep-largest` 仅适用于确有重复实体或噪点碎片的第三方生成件，不能对镜头、按键、耳垫等装配细节盲目使用。

## 美术可辨识性

圆润玩具比例、柔和倒角、明快大色块和少量粗细节，与现有水果、农场、甜品保持同一视觉尺度。避免细文字、极黑大面、细长天线、电线或薄到侧视消失的屏幕。低金属度通过配色与边缘明暗表达金属质感。

首批辨识表：

| id | 主色 / 轮廓 | 必须保留的识别特征 | 允许简化 |
| --- | --- | --- | --- |
| phone | 珊瑚红 / 长矩形 | 屏幕、四枚大应用块、听筒、后置双摄 | 接口、文字、真实品牌 UI |
| laptop | 薄荷绿 / 打开折角 | 明确开合角、屏幕、键盘、触控板、转轴 | 单键字符、接口、内部结构 |
| camera | 金黄 / 凸出圆镜头 | 机身、镜筒与玻璃层、取景器、快门、握把 | 刻度、品牌、真实光学结构 |
| headphones | 紫 / 拱形 | 头梁、左右耳杯、深色耳垫、连接支架 | 细缝、线缆、可动关节 |
| handheld | 蓝与珊瑚红 / 宽横条 | 中央屏幕、摇杆、十字键、四按钮、左右握持区 | 品牌、真实游戏画面、文字 |
| speaker | 水蓝 / 直立长方体 | 两个不同直径的扬声器、前格栅、顶部按钮、状态灯 | 网孔微结构、无线协议标识 |
| mouse | 奶油白 / 椭圆拱背 | 左右按键、滚轮、中缝、侧键、底壳 | 线缆、商标、内部电路 |
| smartwatch | 金黄 / 带状表带 | 独立表壳、圆形表盘、时针、表冠、表带孔 | 数字文字、真实品牌表盘 |
| radio | 玫瑰粉 / 带提手横盒 | 大扬声器、调谐窗、指针、双旋钮、提手 | 频率数字、品牌 |

反面也应有基本物品结构；正视、俯视、背视和缩略图都应检查。只改变颜色不能证明易区分，应同时用纵横比例、折角、环、圆镜头等轮廓区分。

## 验证层次

1. Blender 源网格质量与导出 GLB 回读验证。
2. Khronos glTF Validator 零错误、零警告；报告保存，不以截图替代。
3. 图标 alpha 留白、四视图、64px 目视检查；目视结论由实际查看图像后记录。
4. 从 GLB 读取世界坐标，通过项目真实 hull 采样和 JoltWorld 进行 45 件密堆、15 秒休眠、射线拾取与移除后 5 秒塌落测试。数学接口由 Three.js 适配，明确不是 Cocos 运行时 UI 测试。
5. Creator 导入验证材质、UV、prefab 与图标；最终进入关卡还需验证小屏触控、三消、托盘、冰封及帧率。

不得通过修改旧文件、降低门禁或强制冻结刚体来让报告变绿。若某项预算确实妨碍产品辨识，记录原因并提出具体调整。
